# Todo 示例目标架构

## 目的与设计依据

本仓库只为 AgentForge 提供一个可复现的小缺陷任务。目标是让后续 Agent 在独立工作区把“不存在的 Todo 返回 200”修成 404，并用固定测试验证；不把它扩展成真实 Todo 产品。为减少与缺陷无关的变量，数据只留在进程内，不引入数据库、认证、前端或部署编排。

## 组成部分与数据流

| 部分 | 当前职责、接口与技术 | 与其他部分的关系 |
|---|---|---|
| 客户端 | 任意 HTTP 客户端；演示命令使用 PowerShell `Invoke-RestMethod` | 发送 JSON 请求，接收状态码和 JSON 响应；没有专门的 Web 页面 |
| 服务端 | `todo_app/main.py` 中的 FastAPI 应用；`create_app()` 创建独立实例，`app` 是 Uvicorn 入口 | `POST /todos` 和 `GET /todos/{todo_id}` 承担全部 HTTP 边界 |
| 输入模型 | Pydantic 的 `TodoCreate`，只要求 `title` 为字符串 | FastAPI 在进入创建路由前校验请求体；不承诺标题非空等额外规则 |
| 数据存储 | `create_app()` 内的字典和递增 ID，属于单个应用实例 | 路由直接读写；进程重启后丢失，不能跨实例共享 |
| 行为检查 | `tests/test_todos.py`，pytest + `TestClient` + httpx2 | 通过进程内 HTTP 请求验证接口；缺陷测试在基线上故意失败 |
| 本地运行 | Uvicorn 监听本机 HTTP；`requirements.lock` 固定依赖 | 不部署生产环境，不需要容器或外部服务 |

请求流为：HTTP 客户端 → FastAPI 路由／Pydantic 请求校验 → 当前应用实例的内存字典 → HTTP 状态码和 JSON 响应。测试走相同的路由，但不需要启动独立服务器。

## 当前实现与目标差异

创建、正常查询、实例隔离和非整数路径校验已实现。缺失的整数 ID 当前返回 200 与错误详情，这是唯一刻意保留的业务缺陷；目标行为是返回 404，不能通过跳过测试或修改期望值“解决”。`阶段步骤实现.md` 记录修复顺序。AgentForge 的工作区管理与执行隔离属于另一个项目，不在本仓库实现。
