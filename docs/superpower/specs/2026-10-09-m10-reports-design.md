# M10 Diff 与报告设计

M10 承接已完成的 M9：把固定补丁、独立验收和报告组成可重复的审查流程。沿用 Python 3.11 标准库、Git、pytest 和 Docker，不引入模型、数据库或 Web 服务。

## 组成与数据流

新增 `reporting/` 功能模块：`diff.py` 从固定提交原始文件与 M9 候选快照计算完整变更清单和 Diff；`evidence.py` 校验并复制完整证据；`service.py` 汇总、持久化和查询；`cli.py` 提供 `build/show`。验收模块公开读取指定记录、规则摘要及校验证据的接口，避免报告依赖私有持久化细节。

报告只汇总已有检查，不运行 Docker、不修改候选、不更新 Job 状态。`build` 捕获当前候选，读取最新 M9 候选记录及其指定基线；仅当固定规则、HEAD、全树摘要、测试身份、镜像和证据一致时认可检查结论。没有候选验收、证据缺失或规则不一致为 `unverified`；版本变动为 `stale`；测试失败保持 `existing_failure/new_failure`；完整通过为 `passed`。非法候选拒绝生成正常报告。`passed` 只指固定五项检查通过，人工审查和五项之外的行为始终列为未验证事项。

产物位于工作区根的 `.reports/<workspace_id>/<report_id>/`：`report.json`、可读 `report.md`、`changes.diff`，以及基线/候选的验收 JSON、完整日志和 XML 副本。摘要提供候选实际路径、基线提交、HEAD、摘要、每个变更的字节数与 SHA256、逐项结果、环境/命令、运行身份和全部证据引用。所有产物记录大小和 SHA256，引用是绝对路径。最后发布 `latest.json` 指针。报告不截断 Diff 或日志，超限证据标为未验证；二进制文件列出变更及摘要，并说明无文本 Diff。

`show` 不执行测试：检查保存产物的大小/哈希并重新捕获候选。候选清理后可读取历史报告，明确当前有效性为 false；既有通过记录不能代表已修改版本。生成结束也重新检查候选，防止把新版本与旧检查拼接。

## 边界和验收

沿用 M9 的单文件 256 KiB、全树 4 MiB、2,000 条目边界与 `todo_app/` 修改范围。完整日志上限 8 MiB、XML 1 MiB、验收 JSON 1 MiB；证据只能来自宿主 `.runs/` 的合法 UUID 文件，不跟随链接/重解析点或硬链接，不接受任意外部路径。固定套件仍是一个 404 验收和四项回归。受信任宿主、稳定文件系统的既有边界不升级成恶意候选隔离保证。

验证覆盖文本新增/删除/修改、换行和二进制、缺失验收、失败分类、过期/生成中变动、完整证据复制与校验、非法路径和产物篡改、CLI 退出码。真实 Docker 验证固定补丁到报告、测试失败不称完成、来源不变以及工作区/容器清理。同步既有 README、最终目标和阶段目标；只推进 M10。
